# P2：写操作（可编辑结果） Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 安全地改数据：能映射到「单表 + 主键」的结果可编辑单元格、增行、删行；提交前预览逐行参数化 SQL，**单事务**执行，影响行数 ≠ 1 整体回滚；无主键/视图/别名/表达式结果只读。

**Architecture:** `engine` 新增可选 `Transactional`（`Begin → Tx.Exec/Commit/Rollback`），两驱动用 `database/sql` 事务实现；`app/editable.go` 负责「可编辑判定 + 本地 overlay（改格/增行/删行）+ 参数化 SQL 生成 + 影响行数校验」，纯逻辑、可单测；`ui` 只做交互（弹窗编辑、脏标记、预览确认、刷新/撤销）。**N 张表/K 列元数据来自 A3 的 `ColumnLister`**（含主键），不重造。

**Tech Stack:** Go 1.27.3、`database/sql`、mygo `ui.Modal`/`ui.Table`、现有 `app`/`engine`。

**Spec:** `docs/superpowers/specs/2026-11-05-db-g-roadmap-v2-design.md`（P2 一节）

## Global Constraints

- 不新增依赖；`CGO_ENABLED=0`；全量 `go test -p 1 ./...`。
- **只读是默认**：可编辑判定不通过（多表 JOIN、视图、别名/表达式列、结果里没有全部主键列）时，结果区不提供任何写操作。
- 提交必须**单事务**：任一语句失败或影响行数 ≠ 1 → 全部回滚，错误上抛到 UI。
- 写操作要过 `CapEditableResult` + `engine.Transactional` 双门控；驱动未声明则只读。
- 值参数化（`?`），不拼字符串；预览（只读展示）才内联字面量。
- 文案中文；提交信息 `taskN: …`。每任务收尾绿：`CGO_ENABLED=0 go test -p 1 ./...`、`go vet ./...`。

## Review Focus

1. **误写**：结果行定位必须靠完整主键；同一 UPDATE/DELETE 影响 ≠ 1 行必须回滚，不能"部分成功"。（Task 2）
2. **NULL 与类型**：把 NULL 改成值、把值改成 NULL、数字/字符串/`[]byte` 的参数字面量必须正确（不能把 NULL 当空串写入）。（Task 2）
3. **只读降级**：JOIN、视图、`SELECT a AS x`、`COUNT(*)`、结果缺主键列时一律只读，且 UI 明确提示原因。（Task 1、Task 3）
4. **事务泄漏**：Begin 后任何错误路径都必须 Rollback；成功路径必须 Commit；连接/会话关闭时不能留下悬挂事务。（Task 1）
5. **提交前预览与实际执行一致**：预览里显示的每一行 SQL 与真正参数化执行的操作一一对应（行数、列、WHERE 主键）。（Task 3）

### Task 1: engine 事务能力（可选接口 + 两驱动）

**Files:** Modify `engine/session.go`、`engine/caps.go`（已有 `CapEditableResult`，驱动 `Caps` 追加）、`driver/sqlite/sqlite.go`、`driver/mysql/mysql.go`；Test：`driver/sqlite/sqlite_test.go`、`driver/mysql/mysql_test.go`

**Interfaces:**
```go
type Tx interface {
    Exec(ctx context.Context, query string, args ...any) (int64, error)
    Commit() error
    Rollback() error
}
type Transactional interface { Begin(ctx context.Context) (Tx, error) }
```
驱动：`Caps()` 追加 `CapEditableResult`；`Begin` 用 `db.BeginTx`；`Tx.Exec` 返回 `RowsAffected()`。
sqlite（`SetMaxOpenConns(1)`）事务期间其它查询会排队，属预期。

### Task 2: `app/editable.go` —— 可编辑判定 + overlay + 参数化执行

**Files:** Create `app/editable.go`、`app/editable_test.go`、`app/editable_integration_test.go`

**Interfaces:**
```go
type ColumnInfo struct { Name, Type string; PrimaryKey bool }
type EditPlan struct {
    Kind     string
    Table    string
    Columns  []string // 结果列（必须都能在表列里找到）
    Editable []bool   // 每列是否可改（主键列不可改）
    PKIdx    []int    // 主键列在结果里的下标
    PKNames  []string
}
func BuildEditPlan(kind, table string, resultCols []string, tableCols []ColumnInfo) (*EditPlan, error)

type CellKey struct{ Row, Col int }
type EditSet struct {
    Cells   map[CellKey]any // 改格：结果为界的行下标 + 结果列下标
    Inserts []map[int]any   // 新增行：列下标 → 值（未填的列走库默认）
    Deletes map[int]bool    // 删除：结果行下标
}
func NewEditSet() *EditSet
func (e *EditSet) Count() int
func (e *EditSet) SetCell(row, col int, v any)
func (e *EditSet) ClearCell(row, col int)
func (e *EditSet) MarkDeleted(row int)
func (e *EditSet) RestoreRow(row int)
func (e *EditSet) AddInsert() int          // 返回新行临时下标（len(Inserts)-1）
func (e *EditSet) RemoveInsert(i int)
func (e *EditSet) Clear()

type Op struct { SQL string; Args []any; Want int64 } // Want: 期望影响行数（0 = 不检查）
func (e *EditSet) BuildOps(plan *EditPlan, rows [][]any) ([]Op, error) // 顺序：UPDATE → INSERT → DELETE
func (e *EditSet) Preview(plan *EditPlan, rows [][]any) ([]string, error) // 内联字面量，供确认弹窗
func ApplyOps(ctx context.Context, tx TxLike, ops []Op) error // 逐条执行 + 行数校验；错误即停（由调用方回滚）
type TxLike interface { Exec(ctx context.Context, query string, args ...any) (int64, error) }
```
规则：UPDATE `SET 改动的列`，`WHERE 全部主键`；INSERT 只写已填列；DELETE 按主键；主键列不可改（`Editable[pk]=false`）；结果列必须全部匹配表列（大小写不敏感）且主键列都在结果里，否则 `BuildEditPlan` 报错（UI 据此只读）。

- [ ] Step1 单测：合法计划；缺主键 / 未知列 / 重复列 → 报错；改格生成 UPDATE（参数顺序与 WHERE 主键）；改值→NULL、NULL→值；增行只含已填列；删行按主键；`Preview` 内联值与 `BuildOps` 参数一致。
- [ ] Step2 RED；[ ] Step3 实现；[ ] Step4 GREEN；[ ] Step5 集成测试（sqlite 真库）：改一格提交后库里变化；人为让 UPDATE 影响 0 行（改主键→不存在）→ 返回错误且事务回滚；增/删各一条后数据正确。
- [ ] Step6 commit `task2: 可编辑判定与 overlay（UPDATE/INSERT/DELETE 参数化 + 行数校验）`。

### Task 3: UI —— 改格/增删行/预览提交/刷新/撤销

**Files:** Modify `ui/result.go`、`ui/root.go`、`ui/run.go`（刷新）；Create `ui/editable.go`、`ui/editable_test.go`

**Interfaces:**
```go
// root 字段
editPlan   *app.EditPlan   // 当前结果的可编辑计划（nil = 只读）
edits      *app.EditSet    // 当前结果的本地 overlay（按 runtimeID 隔离 map）
editKeys   map[string]*app.EditSet
editBusy   bool
// ui/editable.go
func (a *root) ensureEditPlan()               // 取单表关系 + 列目录（ColumnLister），构建 plan
func (a *root) editSet() *app.EditSet
func (a *root) beginEditCell(row, col int)    // 打开单元格编辑弹窗
func (a *root) commitEdits()                  // 预览 → 确认 → 事务执行 → 刷新
func (a *root) refreshResult()                // 重跑 lastExecSQL（保留排序/筛选状态）
```
- 结果区：脏格用强调色/加粗，删除行加 `−` 前缀且置灰，增行渲染在末尾（可编辑）。
- 工具条：`编辑格`、`增行`、`删行`、`撤销改动`、`提交`（带改动数徽标）；只读时这些按钮禁用并在工具条提示原因（例："JOIN 结果只读"）。
- 提交：生成 `Preview` 弹窗（只读、可复制），确认后 `Begin` → `ApplyOps` → Commit；失败 Rollback 并把错误显示在结果区。
- 刷新：`refreshResult` 重跑当前语句（同一 runtime，重置 overlay），保持排序/筛选。
- 测试：只读门控（JOIN/视图/缺主键 → 按钮禁用且提示）；改一格 → 提交后结果区新值；提交失败保留 overlay 并显示错误；增行/删行流程；撤销清空 overlay；`ensureEditPlan` 对别名列返回 nil。

- [ ] 五步 TDD；commit `task3: 结果编辑 UI（改格/增删行/预览提交/刷新/撤销）`。

## 升级条件（何时停下来问）

- 需要「行内编辑」（mygo `Table` 不支持内联编辑）才能接受 → 现在是弹窗编辑，若必须内联要评估自绘控件。
- 主键包含 NULL 或结果里主键值重复（非真主键）导致定位不唯一 → 停下来说明并改为只读。
- MySQL 上 `RowsAffected` 对「值未变」的 UPDATE 返回 0（MySQL 默认只算真正改变的行）→ 需要用 `CLIENT_FOUND_ROWS` 或放宽校验为 `<=1`，这是语义取舍，需确认。
