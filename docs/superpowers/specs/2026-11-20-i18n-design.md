# db-g 国际化（中文 / 英文）设计

日期：2026-11-20
状态：**已批准（2026-11-20）**，按本文档编写 `docs/superpowers/plans/` 的分阶段计划并执行。

已拍板的决策：

| 决策点 | 结论 |
|---|---|
| 默认语言 | **跟随系统**：中文系统用 `zh-Hans`，其他语言回退 `en` |
| v1 范围 | 做到 **P3**（UI + app 自定义错误 + AI 回答语言） |
| AI 回答语言 | **跟随界面语言** |
| 驱动层错误 | **不做翻译、不做二次修改**：`engine`/`driver` 返回的报错原样展示，也不改成错误码包装；只有应用自定义的错误提示走 i18n |

## 1. 背景

现状有两个不一致：

- 主窗口、设置、对话框的文案全部硬编码中文；
- 自动更新弹窗是英文的。

已定位根因，不是「两套文案」而是**应用没有声明自己写哪些语言**：

- 更新窗口由 mygo 的 `updater/native` 插件绘制，文本跟随 `mygo.App.Locale()`；
- 本项目没有 `locales` 目录、没有 `mygo.json` 的 `i18n` 配置，也没有 `App.SetLanguages`；
- 因此 `App.Locale()` 恒为 `en`，而 updater 内置了 `zh-Hans` 却选不到，只能显示英文。

mygo 已提供完整的方案：catalog（ARB/ICU JSON）→ `mygo generate` 生成类型安全的 Go 函数 → `App.SetLocale`
实时切换并持久化 → 所有原生控件、菜单、日期/数字格式化与 updater 跟随。本项目应当接入它，而不是自建
一套翻译表。

本设计取代 `2026-11-05-db-g-roadmap-v2-design.md` 中「i18n：界面保持中文」的非目标。

## 2. 目标与非目标

### 目标

1. 设置窗口内可切换 **跟随系统 / 简体中文 / English**，切换即时生效，无需重启。
2. 主窗口、设置、对话框、右键菜单、提示、状态栏、导出/导入、同步、AI 面板等**用户可见文案**全部可翻译。
3. 自动更新弹窗跟随应用语言（中文 / 英文）。
4. 语言选择持久化；发布构建与开发构建互不干扰。
5. 现有 1000+ 处中文文案可渐进迁移，未迁移处退回中文，不会白屏或空白。
6. 测试可稳定断言中文（固定测试语言），并有一套英文冒烟测试。

### 非目标

1. 第三种语言（架构支持，但本次只交付 `en` + `zh-Hans`）。
2. 数据库值、列名、SQL 关键字、表名、文件路径、导出数据的翻译。
3. 日志文案（诊断信息保持现有中文，便于检索）。
4. 数据库服务端返回的原始错误（英文/中文由服务端决定，原样展示）。
5. RTL 布局、区域格式（日期/数字）个性化。ICU 已具备能力，需要时单独做。

## 3. 现状量化

用 Go AST 统计非测试、非生成代码中的中文字符串字面量：

| 范围 | 字面量数 | 说明 |
|---|---:|---|
| `ui/` | 776 | 界面文案主体，`result.go` 114、`settings.go` 110、`sidebar.go` 93 |
| `app/` | 169 | 校验/保存/导出/自举/外观错误，多数直接显示在 UI |
| `ai/` + `ai/plan/` | 40 | 提示词与计划解析错误 |
| `sync/` | 21 | git / 密钥错误 |
| `driver/*` + `engine/` | 18 | 打开连接、DDL、EXPLAIN 的用户可见错误 |
| 合计 | 1027（唯一 845） | 约 111 个带 `%s`/`%d` 占位符 |

另有约 7 个**包级标签表**（`keyActions`、`themeSchemeOptions`、`themeAccentOptions`、`connKinds`、
`objectKinds`、`tagColorSpecs` 等）。它们必须在渲染时取文案，不能在建表时固化，否则切换语言后要重启。

## 4. 技术选型

| 方案 | 结论 |
|---|---|
| **mygo catalog + `mygo generate`（采用）** | 自带 ICU MessageFormat、复数规则、CLDR 数字/日期、语言匹配、`SetLocale` 持久化，并驱动 mygo 控件与 updater |
| 自建 `map[string]string` + 手写 `tr()` | 需要自己实现复数、占位符校验、语言匹配、持久化；updater 仍要单独接，重复造轮子 |
| 以中文原文为 key 的 gettext 风格 | 格式串互相冲突、无法校验占位符类型、中文原文改动会让翻译静默失效；且 mygo 生成器走 key 模式 |

### 语言与源语言

- 目录：`locales/`
- **源语言 `en`**：`locales/en.json` 是唯一完整的源目录，key 为英文语义名。
- 翻译：`locales/zh-Hans.json`。
- 选择 `en` 作源语言的依据：mygo 在用户语言匹配不到任何 catalog 语言时回退到**源语言**。若源语言是
  `zh-Hans`，日语/法语/俄语用户会看到中文；源语言为 `en` 才符合「非中文用户回退英文」的预期。
- 代价：迁移时每条纹样同时产出英文（源）与中文（译文）。中文原文已在代码里，英文本来也必须写，
  这是交付英文模式的固有成本，不是额外返工。

`mygo.json` 增加：

```json
"i18n": { "dir": "locales", "source": "en" }
```

`mygo generate`（或 `mygo dev` / `mygo build`）会生成 `locales/catalog_gen.go`：
每个 key 一个类型安全的函数，参数类型来自 `@key.placeholders`，并自动 import
`_ "github.com/egoist/mygo/locales/zh-Hans"`，让 mygo 自身控件也显示中文。生成文件**提交进仓库**，
`go build` / `go test` 不依赖 CLI。

调用形态：

```go
import "db-g/locales"

ui.Text(c, locales.SettingsTitle())
ui.Text(c, locales.ResultLoadedRows(n))   // {n, plural, one {# row} other {# rows}}
```

## 5. 分层与 import 规则

```
main.go ──> ui ──> locales ──> mygo/i18n
              └──> app ──> locales（P3 起，仅文案）
```

- `locales/` 是生成的叶子包，只依赖 `embed` 与 `github.com/egoist/mygo/i18n`。
- `ui/` 全面使用 `locales`；`main.go` 负责启动时应用语言偏好并保证 `locales` 已注册。
- **文案归属边界**：
  - `ui/`：所有界面文案，第一优先级。
  - `app/`：用户可见的校验/保存/导出错误，P3 迁移；需要更新 AGENTS 允许 `app` import `db-g/locales`
    （它不是 UI 框架，只是字符串目录）。`engine` 保持「只用标准库」不变。
  - `engine` / `driver` / `sync`：不引入 locales。用户可见错误（约 20 条）在 P4 以**错误码/哨兵错误**返回，
    由 UI 翻译；数据库原始错误原样展示。
  - `ai/prompt.go`：提示词不是 UI 文案，不直接翻译；P3 起把当前界面语言传给提示词，要求模型用同语言回答。
  - 日志：不翻译。

## 6. 语言设置与持久化

### 设置入口

`ui/settings.go` 的 `settingsSections()` 新增一个分区「语言 / Language」，放在「外观」之后：

- 单选：跟随系统（`""`）/ 简体中文（`zh-Hans`）/ English（`en`）。
- 选择后立即调用 `mygo.App.SetLocale(tag)`；原生 UI 每帧重建，下一帧即为新语言。
- 选项名称按惯例用自身语言书写：`系统默认` / `简体中文` / `English`。

### 持久化

新增 `app.LocalizationPrefs` → `<config>/<db-g|db-g.dev>/locale.json`：

```json
{ "locale": "" }
```

- `""` = 跟随系统；否则为 `zh-Hans` / `en`。
- 单独文件而不是塞进 `theme.json`：语言和外观是两件事，且 mygo 自身的语言文件在另一路径，
  这样发布/开发构建的配置目录继续统一由 `app.AppConfigDir()` 决定。
- 启动顺序（`main.go`）：加载 `locale.json` → 确保 `db-g/locales` 已注册 → `mygo.App.SetLocale(pref.Locale)`
  → `mygo.Use(updaterNative.Plugin)` → 开窗。
- 设置页修改：写 `locale.json` + `SetLocale`。**不读 `App.ChosenLocale()`**，因为它要求在主线程序列化，
  headless 测试会等待主线程；设置页只读自己缓存的 `root.localePref`。
- `MYGO_LOCALE` 环境变量仍可临时覆盖（`mygo dev -lang en`），测试用它固定语言，不写用户配置。

### 更新弹窗

无需改 updater 代码。catalog 注册后 `App.Locale()` 能解析到 `zh-Hans`，updater 内置中文自动生效；
设置切换后 `updater.text()` 按新语言重建。验收时分别用中文/英文打开更新窗口检查。

## 7. 文案规则

### key 命名

- 小写下划线起头的小驼峰？**统一用 lowerCamelCase 语义名**，按区域前缀排序：
  - `common*`：`commonSave`、`commonCancel`、`commonDelete`
  - `settings*`：`settingsAppearance`、`settingsLanguageHint`
  - `result*`：`resultLoadedRows`、`resultAffectedRows`
  - `conn*`、`console*`、`sync*`、`ai*`、`export*`、`keymap*`
- 一个文案多处复用（保存/取消/删除）用一个 key，不按位置复制。
- 带参数的消息写成 ICU 模板，占位符类型写进源目录 metadata：

```json
"resultLoadedRows": "{n, plural, one {# row} other {# rows}}",
"@resultLoadedRows": {
  "description": "结果区执行中的进度提示",
  "placeholders": { "n": { "type": "int", "example": "192" } }
}
```

### 必须翻译

按钮、标签、标题、占位符、Tooltip、右键菜单、空态/只读原因、确认框、错误提示、状态栏、
设置导航、快捷键动作名、数据源类型名、导出/导入格式名、AI 面板文案。

### 不翻译

- 日志 message 与 `LogInfo/LogWarn/LogError` 的参数。
- 持久化 ID 与枚举值：`ThemeScheme*`、`ThemeMode*`、keymap `ID`、连接 `kind`、Excel/JSON/CSV 格式键。
- SQL、标识符、列名、表名、schema 名、文件路径、数据库返回值。
- 测试里的断言文案（继续中文，用固定语言跑）。
- `app.DisplayName`（品牌名 DB-G）与版本号。
- 服务端错误原文；只翻译 UI 自己的前缀（如「连接失败：」）。

### 不要在包级变量里固化文案

`keyActions`、`themeSchemeOptions`、`themeAccentOptions`、`connKinds`、`objectKinds`、`tagColorSpecs`
改成「存 key/函数，渲染时取文案」：

```go
type keyAction struct {
    ID    string
    Label func() string // 原 Label string
    ...
}
```

或存 `labelKey` 由 `locales.In(locale)` 解析。**不得**在 `init`/包级 var 里调用 `locales.Xxx()`。

### 组合文案

- `"已接收 " + n + " 行"` → `locales.ResultLoadedRows(n)`（英文复数自动正确）。
- `fmt.Sprintf("%d 秒", n)` → ICU `{n, number} 秒` 的英文/中文模板。
- 状态/错误前缀与细节分开：`locales.ConnFailed() + ": " + err` 中的分隔符进模板，避免中英标点混搭。

### 字体与排版

mygo 文本引擎按语言选择字形，无需额外字体配置；英文文案更短，布局以现有弹性布局为主，
验收时检查固定宽度控件（设置导航 168px、按钮组）是否溢出。

## 8. 渐进迁移计划

原则：按「用户每天看到的先后」排，每阶段可独立发布，未迁移处保持中文回退。

### P0 脚手架（先让语言能切、更新弹窗正确）

1. `mygo.json` 加 `i18n`；建 `locales/en.json`（先放 10–20 条骨架文案）与 `locales/zh-Hans.json`；
   跑 `go tool mygo generate` 提交 `catalog_gen.go`。
2. `app/locale.go`：`LocalizationPrefs` 加载/保存/归一化 + 测试。
3. `main.go` 启动应用偏好；`ui/settings.go` 新增「语言」分区。
4. `ui` 测试 `TestMain` 固定 `MYGO_LOCALE=zh-Hans`（仅当环境未设置），保证现有断言不变。
5. 验收：中文系统打开更新窗口为中文；切换 English 后主窗口少量已迁移文案与更新窗口变英文；重启保持。

### P1 主窗口骨架

`ui/titlebar.go`、`sidebar.go`、`tabs.go`、`result.go` 的进度/工具条/分页/空态、`resultfooter.go`、
`history.go`、`keymap.go` 动作名、`theme_schemes.go` 等包级标签表、设置导航与「外观/语言/字体/结果/控制台」
五个分区。验收：主窗口日常查询路径无中文残留（英文模式下）。

### P2 对话框与剩余设置

连接弹窗/测试连接、对象树右键菜单与 DDL、外部控制台、导出/导入、同步、AI 面板/设置/调试、
安装/升级、日志/开发分区、guard 错误条。验收：所有弹窗、菜单、提示在英文模式下为英文。

### P3 app 层用户可见错误与 AI 语言

- AGENTS 允许 `app` import `db-g/locales`；迁移 `app/conn.go`、`consolemgr.go`、`export.go`、
  `editable.go`、`selfinstall.go`、`themeprefs.go`、`syncservice.go` 的用户可见文案。
- AI：把 `mygo.App.Locale()` 传入提示词，要求回答与界面语言一致；`ai` 包不 import mygo。

### P4 规范收尾（不碰驱动错误）

- **不迁移** `engine` / `driver` 的错误：按已批准决策，驱动层报错原样展示，不改写、不包装、不做错误码。
- `sync` 返回的底层 git/密钥错误同样原样展示；只有 UI 自己的前缀走 catalog。
- `make i18n-status` 脚本（AST 扫描）报告剩余中文字面量；迁移完成后设为 CI 检查（`ui/` 应为 0，
  允许日志/测试/注释/驱动错误白名单）。
- 文档：`Readme.md` 功能清单、`AGENTS.md` 文案规范（删掉「一律中文，不做 i18n」）、
  roadmap 的非目标标注为已撤销。

## 9. 测试策略

1. **中文回归**：`ui` 等包含 headless 测试的包加 `TestMain`，未设置时 `MYGO_LOCALE=zh-Hans`；
   现有 `tt.HasText("执行 (Ctrl+Enter)")` 等断言保持不动。
2. **catalog 一致性**（`locales/catalog_test.go`，非生成）：zh/en key 集合相同；占位符名与类型一致；
   英文目录不含 CJK；ICU 能解析（`mygo i18n check` 同款校验）。
3. **英文冒烟**：在 `MYGO_LOCALE=en` 下运行少量 headless 用例（`-run TestI18nEnglish`），断言设置导航、
   主按钮、结果空态为英文。通过 Makefile/CI 单独跑一条命令，不在默认中文测试进程里切换全局语言。
4. **设置交互**：headless 点击「English」→ 断言持久化文件内容与 root 缓存的 `localePref`；
   不直接调用会触碰真实用户目录的 API（测试用 `t.TempDir()` 注入路径）。
5. **更新弹窗**：catalog 注册与 `App.Locale()` 的解析用 mygo 的单元行为覆盖；人工验收中英文各开一次。

## 10. 风险与缓解

| 风险 | 缓解 |
|---|---|
| 845 个 key 迁移量大、容易混入半中半英 | 分阶段 + AST 扫描脚本量化剩余；源语言 `en`，缺中文译文时英文兜底（可接受） |
| 包级标签表固化语言，切换需重启 | 本设计明确改为函数/渲染期解析；P1 审计全部 `var ... []struct{label...}` |
| 英文文案变长导致布局溢出 | 用后台设置页/连接弹窗等固定宽度界面做验收；必要时放宽固定宽度或 `SingleLine`+Tooltip |
| 测试依赖中文文案 | `TestMain` 固定 `MYGO_LOCALE=zh-Hans`；英文测试独立进程 |
| app 层 import locales 破坏分层 | 仅允许生成的 `locales` 叶子包；`engine`/`driver`/`sync` 不引入，改用错误码 |
| mygo `SetLocale` 自身持久化与本项目 `locale.json` 双写 | 以 `locale.json` 为准，启动时总是用它调用 `SetLocale`；不读 `ChosenLocale` |
| AI 回答语言与界面不一致 | P3 把界面语言传给提示词；属于模型行为，UI 文案不受影响 |

## 11. 待确认决策

1. **默认语言**：推荐「跟随系统」（中文系统中文、其他英文）；备选「默认中文，用户手动切英文」。
2. **v1 范围**：推荐做到 P3（UI + app 层用户可见错误 + AI 语言），P4 收尾随后；
   备选只做 UI（P0–P2），app/driver 的错误暂时保留中文/英文原文。
3. **AI 回答语言**：推荐随界面语言（英文界面下要求英文回答）；备选保持现状（提示词中文，回答可能中文）。

以上确认后，按 superpowers 流程编写 `docs/superpowers/plans/` 的分阶段实施计划。
